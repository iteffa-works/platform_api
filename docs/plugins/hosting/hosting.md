# Плагін «Хостинг» (`api/src/plugins/hosting`) — еталон плагіна

Хостинг як послуга: тарифи, замовлення й продовження з балансу, керування акаунтами й серверами в адмінці,
ресурси (сайти, DNS, пошта, БД, FTP, SSL, cron) — у кабінеті клієнта. Панель — провайдер **ISPmanager 6**.
Інтерфейс — server-driven UI ([README](README.md)): у web коду плагіна немає.

**Ізоляція.** Плагін не імпортує інші плагіни. Звʼязок з платформою — лише:
- **порти** `flowaxy/services`: `use('wallet' | 'users' | 'access' | 'notifications')` — контракти в ядрі, реалізації реєструють плагіни billing / auth / notifications;
- **хуки** `flowaxy/hooks` — події плагіна й фільтр ціни;
- `flowaxy/db`, `flowaxy/ui`, `shared/*` (HTTP, гроші, шифрування).

**Копія даних панелей.** Обʼєкти панелі зберігаються в БД (`hosting_resources`); кабінет і адмінка читають звідти,
без запитів до панелі. Синхронізація — раз на `HOSTING_JOB_INTERVAL_MINUTES` (10 хв) і одразу після змін через платформу;
у БД пишеться лише змінене (hash обʼєкта, використання акаунтів, IP сервера).

## 1. Структура

```
hosting/
  index.ts            маніфест плагіна (тонкий): права, ui, маршрути, init
  module.ts           HostingModule — корінь композиції: створює й звʼязує сервіси
  config.ts           HostingConfig — налаштування (env)
  hooks.ts            типи хуків (declaration merging) + підписники: журнал, сповіщення (порт notifications)
  domain/
    models.ts         Sequelize: HostingServer, HostingPlan, HostingAccount, HostingResource (копія обʼєктів панелі)
    rules.ts          чисті правила: логін, пароль, домен, cron, дати, доплата (+ rules.test.ts)
    input.ts          розбір вводу форм: текст, лічильники, дата, країна, IP (публічні / приватні)
    url.ts            нормалізація http(s)-адреси панелі
  providers/
    contracts.ts      контракт PanelClient: accounts, sites, dns, mail, databases, ftp, ssl, cron, system
    registry.ts       ProviderRegistry (id → провайдер)
    ispmanager6/      transport.ts (HTTP, сесія), mapper.ts, resources/*.ts (клас на розділ), provider.ts
  services/           класи бізнес-логіки
    server.service    сервери: облік, підключення, перевірка, огляд системи, користувачі панелі (з копії), діагностика
    plan.service      тарифи
    account.service   акаунти: адмінські дії й дії власника (користувачі — порт users)
    order.service     замовлення, продовження, зміна тарифу — гроші (порт wallet)
    mirror.service    копія обʼєктів панелі: reconcile (лише змінене), читання, лічильники (+ mirror.test.ts)
    sync.service      синхронізація: сервер за прохід, розділи власника після зміни, використання, IP сервера
    resource.service  ресурси акаунта в кабінеті: читання з копії; зміна → панель → копія → хук
    lifecycle.service фонове завдання: строки, блокування, самовідновлення, синхронізація
    presenter.ts      подання моделей без секретів;  panel-call.ts — PanelError → 502, settle
  http/               guards.ts (доступ через порт, json / created) + admin / cabinet .routes.ts
  ui/                 kit.ts, format.ts, grid.ts, messages/, pages/admin/* (server/* — сторінка сервера), pages/cabinet/*,
                      sections/* — розділи кабінету (PanelScope одного акаунта)
  migrations/  cli/probe.ts (перевірка підключення до панелі)
```

**Правило:** маршрут лише читає запит і викликає метод сервісу; сервіс не знає про HTTP-відповідь і журнал —
оголошує подію хуком; побічні ефекти — у підписниках (`hooks.ts`). Провайдер не знає про БД і гроші.

## 2. Провайдери

| | ISPmanager 6 |
|-|--------------|
| Адреса | `https://host:1500` (суфікс `/ispmgr` прибирається) |
| Протокол | POST `out=json`, сесія з повторним входом |

Нова панель: клас з `HostingProvider` + `PanelClient` (розділи можна наслідувати від базового класу, як `IspResource`),
рядок у `createProviderRegistry()`. Сервіси, сторінки, синхронізація й білінг не змінюються.

### ISPmanager 6 — відповідність функцій

| Розділ | Функції панелі |
|--------|----------------|
| Користувачі | `user`, `user.edit`, `user.suspend` / `resume`, `user.delete`, `preset`, `session.newkey` (вхід без пароля) |
| Сайти | `webdomain`, `webdomain.edit`, `webdomain.delete` |
| DNS | `domain`, `domain.edit` / `delete`, `domain.record`, `domain.record.edit` / `delete` |
| Пошта | `emaildomain(.edit/.delete)` (`ipsrc` — перша IP з форми), `email(.edit/.delete)` |
| БД | `db`, `db.edit` (новий користувач `user=*`), `db.delete` (ключ `імʼя->сервер`) |
| FTP / SSL / cron | `ftp.user(.edit/.delete)`, `sslcert`, `scheduler(.edit/.delete)` (режим expert; список — лише від імені власника) |
| Система | `whoami`, `license.info`, `sysinfo`, `services`, `ipaddrlist`, `phpversions` |

Особливості, перевірені на 6.155: у режимі `su` списки не мають колонки `owner`; `quota_used` / `quota_total` — МіБ (0 — без ліміту).

## 3. Адмінка — керування хостингом

Один пункт меню «Хостинг» (група «Послуги»); розділи — вкладки зверху з лічильниками: **Огляд · Акаунти · Сервери · Тарифи** (`ui/section.ts`). Сторінки сервера й акаунта — під своєю вкладкою; вкладки сервера — другорядні («таблетки»). На огляді — «Запуск хостингу» (кроки до першого замовлення, зникає, коли все готово) і «Синхронізувати все».

| Сторінка | Що |
|----------|----|
| `/admin/hosting` | огляд: активні / заблоковані / закінчуються, дохід за місяць, сервери, найближчі строки |
| `/admin/hosting/accounts` | акаунти: фільтр стану / сервера / тарифу, пошук (логін, примітка, email), створення / привʼязка |
| `/admin/hosting/accounts/:id` | **картка акаунта**: стан, власник, тариф і строк, використання; форма керування (тариф, строк, автопродовження, примітка); ресурси (кількості з копії); синхронізація, блокування, вхід у панель, видалення |
| `/admin/hosting/servers` | сервери: підключення ISPmanager, стан синхронізації, перевірка, вмикання |
| `/admin/hosting/servers/:id` | **сервер**: Огляд (синхронізація, навантаження, ресурси, система, служби, PHP, IP) · Користувачі панелі (привʼязка до платформи, вхід від імені) · Налаштування |
| `/admin/hosting/plans` | тарифи й **шаблони панелі** (з ISPmanager автоматично): створення тарифу з шаблону, попередження «шаблону немає на сервері» (лінійка — [hosting-plans.md](hosting-plans.md)) |

Адмінка не дублює кабінет: сайтами, поштою й DNS клієнтів адміністратор не керує (для підтримки — «Увійти в панель»
від імені користувача). Права: перегляд — `hosting:view`, зміни — `hosting:manage` (+ `admin.panel:view`).

## 3a. Кабінет клієнта

| Сторінка | Що |
|----------|----|
| `/app/hosting` | мої акаунти: Доступні / Видалені, тариф і строк, сайти, диск, розташування; швидкі дії; «Замовити новий» |
| `/app/hosting/order` | тариф → строк → країна → імʼя; липкий підсумок з оплатою з балансу; пароль показується один раз |
| `/app/hosting/:id` | шапка (стан, сервер, дії), показники, продовження, зміна тарифу; вкладки **Огляд (швидкий старт, доступ) · Сайти · DNS · Пошта · Бази даних · FTP · SSL · Cron · Налаштування** |

Розділи кабінету (`ui/sections/*`, `PanelScope` одного акаунта) читають копію в БД. REST `/cabinet/hosting/:id/panel/*`:
власник — завжди логін акаунта; змінювати / видаляти можна лише обʼєкти, що є в копії цього власника (інакше 404);
записи DNS — лише власних зон (з панелі через кеш); заблокований акаунт — 403; 60 змін / хв.

## 3b. Синхронізація

| Що | Як |
|----|----|
| Сервер (фонове завдання) | користувачі, сайти, DNS-зони, поштові домени й скриньки, БД, FTP, SSL — один запит на розділ для всіх власників; cron — по привʼязаних акаунтах; IP сервера |
| Після зміни в кабінеті | розділ власника (напр. сайти) — одразу |
| «Оновити дані» (кабінет / картка / сервер) | використання з панелі + усі розділи власника / сервера |
| Запис у БД | лише нові / змінені (hash) / зниклі обʼєкти; використання акаунта — якщо змінилось; стан сервера — один UPDATE |
| IP сервера | з панелі, лише публічні адреси (NAT / loopback / link-local ігноруються); родина, якої панель не дала, лишається з налаштувань |
| Помилка | `syncError` сервера (адмінка показує), копія лишається попередня |

## 3c. Шаблони панелі → тарифи

| Що | Як |
|----|----|
| Звідки | ISPmanager: список `preset`, ліміти — форма `preset.edit` кожного шаблону (`limit_quota`, `limit_webdomains`, `limit_db`, `limit_emails`, …; порожньо — без обмеження, `0` — заборонено) |
| Коли | разом із синхронізацією сервера (10 хв) і кнопкою «Оновити шаблони» на сторінці тарифів |
| Де | копія `hosting_resources` (розділ `package`), на кожен сервер окремо |
| Тариф | `package` = імʼя шаблону; диск і сайти тарифу оновлюються з шаблону автоматично (пишуться лише зміни); ціна, назва, опис — лише в платформі |
| Новий тариф | у таблиці шаблонів — «Створити тариф»: форма з назвою (`flx-host-plus` / «Flowaxy Plus» → `plus` / «Plus»), шаблоном і лімітами; ціна 0 — Free |
| Перевірка | тариф, чийого шаблону немає на увімкненому сервері, підсвічується — замовлення на тому сервері впало б |
| Звірка полів | «Поля панелі» в рядку шаблону — сирі `limit_*`; діагностика сервера — `samplePresetForm` |

## 4. Гроші (порт wallet)

| Дія | Правило |
|-----|---------|
| Замовлення | ціна (фільтр `hosting.order.price`) × місяці; списання й `pending` — одна транзакція; панель відмовила → refund |
| Продовження | + місяці від `paidUntil` або сьогодні; рядок акаунта блокується |
| Зміна тарифу | доплата `(нова − стара) × залишок_днів / 30`; дешевший — без повернення; збій панелі → refund |
| Автопродовження / несплата | фонове завдання: списати за місяць або заблокувати; оплата → розблокування |
| Видалення за несплату | лише `HOSTING_DELETE_AFTER_DAYS` > 0 |

## 5. Хуки (інтеграція з іншими модулями)

| Дія | Коли |
|-----|------|
| `hosting.account.created` `{account, source}` | замовлення / адмінка |
| `hosting.account.renewed` `{months, automatic}` · `plan_changed` `{plan, costCents}` | оплата |
| `hosting.account.suspended` `{reason}` · `resumed` · `deleted` · `updated` · `expiring` | життєвий цикл |
| `hosting.account.panel_login` · `password_changed` | дії власника |
| `hosting.panel.changed` `{serverId, section, action, name, client}` | зміна ресурсу в кабінеті / вхід адміністратора від імені |

| Фільтр | Значення |
|--------|----------|
| `hosting.order.price` | ціна в копійках `{plan, months, userId, kind}` — знижки, промокоди, акції |

Підписники за замовчуванням (`hooks.ts`): журнал дій і сповіщення. Інший модуль підписується так само:
`hooks.addAction('hosting.account.created', handler, { owner: 'crm' })`.

## 6. Безпека

| Загроза | Захист |
|---------|--------|
| Облікові дані панелі | AES-256-GCM (`APP_SECRET`), розшифровуються лише в `ServerService.client()`; у web — ніколи |
| Транспорт | TLS-перевірка за замовчуванням; POST (паролі не в URL); таймаут 20 с; ≤ 10 МБ; без редиректів |
| IDOR | кабінет шукає акаунт за `id + userId` → 404; обʼєкти — лише свого власника за копією |
| Ін'єкції в панель | валідація: домен, імена (БД, FTP, скриньки), розклад і команда cron (один рядок), каталог FTP без `..`, тип DNS-запису |
| Системні обʼєкти | зарезервовані логіни (root, admin, mysql…) |
| Подвійна оплата | одна операція на користувача, блокування рядка, 5 замовлень / 10 хв |
| Навантаження | читання — з БД; 60 змін / хв на користувача; кеш сесії панелі; синхронізація — послідовно по серверах |
| Паролі | генерація 16 символів (крипто-ГВЧ), показ один раз; власні — ≥ 10, різні класи |
| Діагностика | лише `manage`; поля pass / secret / key / token / auth / dkim маскуються |

Для production: окремий адміністратор панелі (не root) з доступом лише з IP платформи; після передачі пароля
в чат / листом — змінити його.

## 7. Перевірено

- **Unit**: правила, транспорт ISPmanager, хуки, hash копії, IP за родиною / приватні.
- **Синхронізація** (перевірено до прибирання Sandbox): перший прохід заповнює копію; повторний без змін у панелі — 0 записів.
- **Рендер усіх сторінок** адмінки й кабінету (усі вкладки) — без звернень до панелі, 1–20 мс.
- **E2E ISPmanager 6.155** (`isp.flowaxy.com`, до переходу на копію): читання всіх розділів; створення й видалення тестових
  обʼєктів, блокування, вхід від імені, акаунт платформи.

## 8. Далі

Випуск Let's Encrypt, знижки за строк (фільтр `hosting.order.price`), провайдери HestiaCP / DirectAdmin,
блокування в БД для синхронізації з кількох інстансів API.
