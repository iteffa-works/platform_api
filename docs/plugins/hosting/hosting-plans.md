# Тарифи хостингу

Лінійка: **Free · Start · Plus · Pro · Max**. Один тариф платформи (`hosting_plans`) = один шаблон
користувача в ISPmanager (`package` = імʼя шаблону). Загальна архітектура плагіна — [hosting.md](hosting.md).

> Ціни й ліміти — стартові орієнтири. Перед запуском звірити із собівартістю сервера.

## 2. Шаблони в ISPmanager

Створюємо в ISPmanager: **Шаблони → Новий шаблон**. Нижче — окрема таблиця на кожен шаблон, поля в тому
порядку, як у формі. «не обмежено» = залишити поле порожнім (кнопка ∞). `0` = заборонено.

Формат назви `flx-<продукт>-<тариф>`: `flx` — наш бренд (відділяє від стандартних шаблонів панелі),
`host` — лінійка; майбутні лінійки — `flx-vps-*`, `flx-reseller-*`. Лише малі латинські літери й дефіс.
Назву після створення не змінюємо — на неї посилається платформа.

### 2.6. Пояснення до полів

- **WWW-домени** = сайти; **Доменні імена** = DNS-зони (свій домен і паркування, тому їх більше, ніж сайтів).
- **Листів на годину** обмежуємо навіть на Max — один зламаний сайт інакше заспамить IP усього сервера.
- **Процесорний час** і **Оперативна памʼять** — ліміти **на процес** (не на акаунт). Якщо довгі скрипти
  (імпорт, бекап CMS) обриваються — піднімаємо процесорний час, а не памʼять.
- Обмеження «ядер на акаунт» шаблон не задає — це рівень cgroups / CloudLinux, окреме рішення.
- **Обробники Apache** діють лише якщо сайти йдуть через Apache; у режимі Nginx + PHP-FPM поле ні на що не впливає.
- Єдиний режим PHP — **FastCGI (PHP-FPM)**: кожен користувач працює від свого імені, ізольовано.
  PHP як модуль Apache на спільному сервері небезпечний (усі сайти від одного користувача), CGI — повільний
  й зайва поверхня атаки.
- **Технічний домен** для Free — це і є його адреса `<імʼя>.<технічний-домен>`; без нього Free не працює.
  Для платних — сайт видно ще до того, як клієнт перенаправить DNS свого домену. Задається в налаштуваннях
  сервера ISPmanager; для Free бажано окремий, щоб його репутація не зачіпала основний домен.
- **Free:** `Доменні імена = 0` — сайт живе лише на технічному домені. Перевірити на тестовому користувачі,
  що панель дозволяє створити сайт на технічному домені при нулі доменних імен.

## 3. Правила для Free

Шаблон закриває ресурси, решту робить платформа:

- Реєстрація з підтвердженням email **і телефону**, 1 Free-акаунт на користувача.
- Вихідна пошта закрита шаблоном (скриньки й листи = 0); на сервері також закрити `mail()` / порт 25 для Free.
- Неактивний 30 днів (немає входів і трафіку) → попередження → призупинення → видалення через 14 днів.
- Окремий сервер або IP для Free, щоб не ділити репутацію з платними.
- У кабінеті — кнопка «Перейти на Start»: зміна шаблону зберігає сайт, файли й бази.

## 5. Чому такі назви

- Порядок **Plus < Pro < Max** клієнт уже знає з підписок (ChatGPT, Claude, Apple) — пояснювати не треба.
- Одне коротке слово латиницею однаково читається українською й англійською, в `slug` і в імені шаблону.
- Підзаголовок «для кого» дає зрозумілість назв «за призначенням» (Візитка / Магазин) без їхнього мінуса:
  власник магазину не боїться взяти менший тариф, якщо йому вистачає.
- 4 платні тарифи у вітрині, середній (Plus) позначено «Популярний» і він найвигідніший за ціною за ресурс;
  Max — «якір», на тлі якого Plus і Pro здаються недорогими.
- Назви за обсягом RAM («Бізнес 2G … 32G») залишаємо для майбутньої лінійки VPS / Cloud.
- «Хостинг для WordPress / CMS» — не окремі тарифи, а посадкові сторінки, що ведуть на цю ж лінійку.
