# Домени хостингу

Як налаштувати домени інфраструктури: DNS-сервери, панель і технічний домен.
Тарифи й шаблони — [hosting-plans.md](hosting-plans.md), архітектура плагіна — [hosting.md](hosting.md).

## Схема

| Призначення | Адреса | Домен |
|-------------|--------|-------|
| Сайт і кабінет клієнта | `flowaxy.com` | основний бренд |
| DNS-сервери (NS) | `ns1.flowaxy.com`, `ns2.flowaxy.com` | основний бренд |
| Панель ISPmanager | `flowaxy.tools` → `s1.flowaxy.tools`, `s2.flowaxy.tools`, … | окремий домен панелі |
| Технічний домен (Free, превʼю) | `*.flowaxy.date` | окремий домен для сайтів клієнтів |

**Головне правило:** панель і сайти клієнтів — на **різних** доменах. Інакше сайт клієнта може працювати з cookie
поддоменів панелі, а один фішинговий Free-сайт потягне в блок-листи домен разом із панеллю.

Кожен домен — з автопродовженням на кілька років наперед. Втрата `flowaxy.com` зупиняє DNS **усіх** клієнтів.

## 1. DNS-сервери `ns1` / `ns2.flowaxy.com`

Клієнт прописує їх у реєстратора свого домену; однакові для всіх тарифів.

### 1.1. Сервери

- `ns1` і `ns2` — **різні машини з різними IP**, бажано в різних підмережах / дата-центрах.
  Якщо обидва на одній машині, її падіння «вимикає» всі домени клієнтів.
- `ns2` отримує зони від `ns1` (вторинний сервер імен у ISPmanager або DNSmanager). Схему синхронізації
  зон обираємо при підключенні другого сервера.

### 1.2. Реєстратор `flowaxy.com`

NS лежать у тій самій зоні, яку обслуговують, тому потрібні **glue-записи**:

| Хост | IP |
|------|----|
| `ns1.flowaxy.com` | IP сервера ns1 |
| `ns2.flowaxy.com` | IP сервера ns2 |

Після цього змінити NS домену `flowaxy.com` на `ns1.flowaxy.com` і `ns2.flowaxy.com`.

### 1.3. Зона `flowaxy.com`

```
flowaxy.com.        NS   ns1.flowaxy.com.
flowaxy.com.        NS   ns2.flowaxy.com.
ns1.flowaxy.com.    A    <IP ns1>
ns2.flowaxy.com.    A    <IP ns2>
```

### 1.4. ISPmanager

У налаштуваннях DNS сервера вказати сервери імен за замовчуванням `ns1.flowaxy.com.` і `ns2.flowaxy.com.` —
нові зони клієнтів створюються з ними автоматично.

### 1.5. Перевірка

```sh
dig NS flowaxy.com +short                 # ns1.flowaxy.com. ns2.flowaxy.com.
dig @ns1.flowaxy.com flowaxy.com SOA      # відповідає ns1
dig @ns2.flowaxy.com flowaxy.com SOA      # відповідає ns2, serial такий самий
dig NS <домен-клієнта> +short             # після створення зони в панелі
```

## 2. Панель `flowaxy.tools`

Короткий окремий адрес панелі (як `adm.tools` у ukraine.com.ua).

### 2.1. Адреси

- Кожен сервер хостингу — свій піддомен: `s1.flowaxy.tools`, `s2.flowaxy.tools`, …
  (сервери в платформі — `/admin/hosting/servers`).
- `flowaxy.tools` (корінь) — редирект у кабінет `flowaxy.com`: клієнт заходить у панель кнопкою «Увійти в панель»
  з кабінету, без окремого пароля.

### 2.2. DNS

```
flowaxy.tools.       A    <IP сервера кабінету / редиректу>
s1.flowaxy.tools.    A    <IP сервера s1>
```

### 2.3. HTTPS без порту

ISPmanager за замовчуванням працює на `https://<IP>:1500/ispmgr`. Щоб панель відкривалась як `https://s1.flowaxy.tools`:

- сертифікат Let's Encrypt на `s1.flowaxy.tools`;
- nginx на сервері проксує `s1.flowaxy.tools` → `https://127.0.0.1:1500`.

Перевірити, що вхід за ключем (`session.newkey`) і посилання з кабінету ведуть на новий адрес, а не на `IP:1500`.

### 2.4. Правила

- У листах, кабінеті й підказках панель завжди одним адресом — клієнт не повинен бачити `IP:1500`.
- На `flowaxy.tools` **не розміщуємо** сайтів клієнтів — лише панель.

## 3. Технічний домен `flowaxy.date`

Адреси Free-сайтів (`<імʼя>.flowaxy.date`) і превʼю платних сайтів, поки клієнт не переведе DNS свого домену.
Домен свідомо окремий і «жертовний»: його репутація не зачіпає `flowaxy.com` і панель.

> Ризик зони `.date`: її масово використовують для спаму, тож частина корпоративних фільтрів, антивірусів і поштових
> сервісів позначає або блокує посилання на неї. Для Free це прийнятно; якщо скарг стане багато — переїзд на
> нейтральну зону (`.site`, `.online`, `.dev`) змінює лише налаштування технічного домену.

### 3.1. DNS

```
*.flowaxy.date.    A    <IP сервера з Free>
flowaxy.date.      A    <IP сервера кабінету>   ; корінь — редирект на flowaxy.com
```

Якщо Free розміщується на кількох серверах — окремий рівень на сервер: `*.s1.flowaxy.date`, `*.s2.flowaxy.date`.

### 3.2. ISPmanager

- У налаштуваннях сервера вказати технічний домен `flowaxy.date` (або `s1.flowaxy.date`).
- У шаблонах `flx-host-*` поле «Технічний домен» = **розміщувати** ([hosting-plans.md](hosting-plans.md), розділ 2).

### 3.3. Wildcard SSL

Сертифікат `*.flowaxy.date` Let's Encrypt видає **лише через DNS-перевірку (DNS-01)** — HTTP-перевірка для
wildcard не працює. Варіанти:

- зону `flowaxy.date` тримати в DNS-провайдера з API й випускати сертифікат через certbot / acme.sh з його плагіном;
- або випускати сертифікати окремо на кожен сайт (HTTP-01) — простіше, але повільніше й упирається в ліміти Let's Encrypt.

Сертифікат поновлюється автоматично; перевірити, що після поновлення nginx перезавантажується.

### 3.4. Public Suffix List

Без цього `user1.flowaxy.date` може ставити cookie на весь `flowaxy.date` і втручатися в сайти інших клієнтів.
Так зроблено в `github.io`, `herokuapp.com`.

1. Pull request у [github.com/publicsuffix/list](https://github.com/publicsuffix/list) — додати `flowaxy.date`
   у приватний розділ.
2. TXT-запис для підтвердження: `_psl.flowaxy.date. TXT "https://github.com/publicsuffix/list/pull/<номер>"`.
3. Розгляд займає тижні, а браузери підхоплюють список із новими версіями — подавати заздалегідь.

### 3.5. Правила

- На `flowaxy.date` — лише сайти клієнтів: ні панелі, ні кабінету, ні пошти платформи.
- Скарги на фішинг / спам на Free-сайтах — призупинення акаунта (правила Free — [hosting-plans.md](hosting-plans.md), розділ 3).
